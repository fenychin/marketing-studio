# 计费与限额

## 积分模型

- 所有产物按**模型单价 × 数量**计费，成功才扣（失败 0 费用）。
- 新注册送 500；演示租户送 1000。
- 充值档位：500=✦$4.90、2000=✦$19.00、10000=✦$79.00。

## 限额（429 时）

| 限额 | 值 | 应对 |
|---|---|---|
| 通用请求 | ~120 req/min | 退避后重试（Retry-After 头） |
| 生成提交 | 突发 10、~12/min | 排队节奏化提交 |
| 租户并发作业 | 同时 5 个 | 等待现有作业完成 |

## 充值流程

```bash
POST /v1/billing/checkout {"credits": 2000}   # → {sessionId, amountCents}
POST /v1/billing/mock/confirm {"sessionId"}   # 沙箱即时确认（幂等）
GET  /v1/credits                              # 验证余额
```

真实支付渠道经 `POST /v1/billing/webhook`（HMAC 签名）异步确认。

## 预算纪律

1. 任何 > 200 积分的动作，先向用户展示 plan 结果并拿到明确同意；
2. 402 时不要盲目重试——给出两个选项：充值 / 缩小规模（减 count、降 resolution、换模型）；
3. QC 拒收的重渲是免费的，不要为此让用户再付一次。
